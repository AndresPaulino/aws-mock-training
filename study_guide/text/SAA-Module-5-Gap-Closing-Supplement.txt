mostly as distractors or single-question one-liners; recognize them, know their one sentence, and move on.

3. Task-Statement Concepts Covered Thinly Before

3.1 Immutable infrastructure (Domain 2, Task 2.2)

Mutable infrastructure is patched, updated, and reconfigured in place over time -- servers drift, and 'it works on server 3
but not server 7' becomes normal. Immutable infrastructure is never modified after deployment: to change anything, you
build a new artifact (a new AMI, container image, or Lambda version) and replace the running fleet, then discard the old
one. Benefits: consistent, reproducible, easy rollback (redeploy the previous artifact), no configuration drift, and it forces
statelessness.

3.2 Service quotas & throttling for standby environments (Task 2.2)

Service quotas (limits) are PER ACCOUNT PER REGION: on-demand vCPUs, Elastic IPs (5), VPCs (5), Lambda
concurrency (1,000), etc. A DR environment that sits idle in a second Region often has DEFAULT quotas there -- so
when you fail over and try to scale to production size, launches fail against the limit. Design step: request quota increases
in the DR Region ahead of time, matching production, and monitor quota usage with Service Quotas + CloudWatch
alarms (and Trusted Advisor service-limit checks).

 · Throttling: API Gateway (account and per-method/usage-plan limits), Lambda concurrency limits, DynamoDB capacity,
    and AWS API rate limits all return throttling errors; clients should implement exponential backoff with jitter. In a standby
    failover, verify these limits are raised in the DR Region too.

EXAM TIP: 'Failover to the secondary Region failed to scale'  service quotas were never raised there. 'Protect backend
from being overwhelmed'  API Gateway throttling / usage plans.

· NAT Gateway placement cost trap: one shared NAT Gateway across AZs is cheapest in hours but incurs cross-AZ
   data charges and is a single point of failure; one per AZ costs more hours but avoids cross-AZ fees and survives AZ

3.4 VPN bandwidth: single vs multiple tunnels (Task 4.4)

A Site-to-Site VPN connection gives two tunnels of ~1.25 Gbps each, but with a Virtual Private Gateway only one is active
per connection (active/standby). To exceed 1.25 Gbps, terminate VPNs on a Transit Gateway and enable ECMP
(equal-cost multi-path): multiple VPN connections/tunnels aggregate bandwidth (e.g., 4 connections  10 Gbps). Choosing
Direct Connect speeds: pick hosted (50 Mbps­10 Gbps) for moderate steady loads, dedicated 1/10/100/400 Gbps for
large; add a second connection or VPN for resilience.

EXAM TIP: 'VPN throughput is capped around 1.25 Gbps and must increase'  multiple VPN connections on Transit
Gateway with ECMP. 'Consistent multi-Gbps, low latency'  Direct Connect.

3.5 Migrating applications into containers (Task 2.1)

Containerizing a legacy app: write a Dockerfile capturing runtime + dependencies; externalize configuration (environment
variables, SSM Parameter Store, Secrets Manager) and state (S3, EFS for shared files, RDS/DynamoDB for data) so the
container is disposable; push the image to ECR; run on ECS (Fargate for least ops, EC2 for cost/GPU) or EKS if the team

3.6 Secure access to ingestion points (Domain 3, Task 3.5)

Data lakes and streams need locked-down entry points: Kinesis and Firehose via IAM roles/policies and VPC interface
endpoints (no public internet path); S3 ingest via bucket policies requiring TLS + specific principals, presigned URLs for
external uploaders, or Transfer Family with SFTP keys; Lake Formation for column/row-level permissions once data lands;
KMS encryption at rest across all of it; CloudTrail data events for audit of who read what.

Practice Q1. A company's security team must let 300 remote employees reach private EC2 resources in a VPC from
home laptops, authenticating with the corporate identity provider. Which service?

   # Site-to-Site VPN -- connects a network (customer gateway device), not individual laptops.
   # Bastion host with SSH keys -- unmanaged keys, no IdP integration, exposes port 22.
    AWS Client VPN endpoint with SAML federation to the IdP, associated with the VPC subnets. People-to-VPC = Client
   VPN.

Practice Q2. An organization wants developers in 30 accounts to launch only pre-approved, standardized environments
(specific instance sizes, tagged, encrypted) without granting them permissions to create arbitrary resources.

   # AWS Config rules -- detect non-compliance after the fact; don't govern provisioning.
   # Give developers CloudFormation + broad IAM -- arbitrary resources become possible.
    AWS Service Catalog portfolios shared to the accounts, with launch constraints and a launch role that holds the
   permissions. Self-service provisioning of approved products = Service Catalog.

Practice Q3. A pilot-light DR design in a second Region failed during a test: the Auto Scaling group could not launch
beyond 20 instances although production runs 80. Most likely cause and fix?

   # Wrong instance type -- would fail at instance 1, not 20.
   # Route 53 misconfiguration -- unrelated to launch failures.
    Default EC2 vCPU service quota in the DR Region; request quota increases matching production ahead of time and
   alarm on quota utilization. Quotas are per-Region and are a classic DR blind spot.

Practice Q4. A dev/test VPC with minimal outbound traffic pays more for its NAT Gateway than for its instances. Reduce
cost with minimal risk to a non-production environment.

   # Remove outbound access -- breaks package installs.
   # Add a NAT Gateway per AZ -- increases hourly cost.
    Replace with a small NAT instance (t4g.nano) or a single shared NAT Gateway; for low-traffic non-production the
   instance is cheapest. The guide explicitly calls out NAT instance vs NAT Gateway cost.

Practice Q5. A platform team wants all accounts to launch workloads into centrally managed subnets in a shared
networking account, so network controls live in one place. What enables this?

   # VPC peering from each account -- separate VPCs per account, not shared subnets.
   # Transit Gateway -- connects VPCs; doesn't let other accounts launch into your subnets.
    AWS Resource Access Manager to share the VPC subnets with the Organization (VPC sharing). Participants launch
   resources in the shared subnets; the owner controls routing, NACLs, and endpoints.

Practice Q6. Marketing needs Salesforce opportunity data landed in S3 nightly for analysis in Athena, with no custom
integration code. Which service?

   # Lambda calling the Salesforce API -- custom code, auth handling, pagination, maintenance.
   # DataSync -- file/object transfer between storage systems, not SaaS APIs.
    Amazon AppFlow flow from Salesforce to S3 on a schedule, optionally with field mapping and Parquet output. SaaS 
   AWS with no code = AppFlow.
